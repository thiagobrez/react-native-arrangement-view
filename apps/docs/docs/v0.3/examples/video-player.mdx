# Video player

A full-screen player that follows Apple's iPhone Duo guidance: in tabletop, "media can sit at the top, while tappable controls live on a stable base at the bottom". The full example is in the [example app](https://github.com/thiagobrez/react-native-arrangement-view/tree/main/apps/example-expo/src/examples/video-player).

| Posture                     | Layout                                                                              |
| --------------------------- | ----------------------------------------------------------------------------------- |
| Closed, or open flat        | Full-screen video, with controls over it that hide while it plays and return on tap |
| Half-open, tabletop         | The video on the upright half, and controls filling the half on the table           |
| Half-open, held like a book | The video on the leading half, and controls on the trailing half                    |

## The arrangement

Use `arrangement="overlay"`, with the controls as the primary pane. Overlay keeps both panes at full size, the primary in front, until a half-open hinge separates them. It then puts the primary after the hinge: below it in tabletop, or on the trailing side.

```tsx
import { StyleSheet, View } from 'react-native';
import { VideoView, useVideoPlayer } from 'expo-video';
import { ArrangementView } from 'react-native-arrangement-view';

export function VideoPlayer() {
  const player = useVideoPlayer(source, (player) => player.play());

  return (
    <View style={styles.screen}>
      <ArrangementView style={styles.fill} arrangement="overlay">
        <ArrangementView.Primary>
          <Controls player={player} />
        </ArrangementView.Primary>
        <ArrangementView.Secondary>
          <VideoView
            style={styles.fill}
            player={player}
            nativeControls={false}
            contentFit="contain"
          />
        </ArrangementView.Secondary>
      </ArrangementView>
    </View>
  );
}

const styles = StyleSheet.create({
  screen: { flex: 1, backgroundColor: 'black' },
  fill: { flex: 1 },
});
```

Moving between postures doesn't unmount either pane, so the video keeps playing.

## The controls

Inside the controls, [`useArrangementLayout`](../api/use-arrangement-layout) tells the two layouts apart. Overlapping panes have no `axis`; separated ones are `"vertical"` in tabletop and `"horizontal"` held like a book. Over the video, the controls hide a few seconds after the last touch while it plays. In their own region they stay visible.

```tsx
import { useArrangementLayout } from 'react-native-arrangement-view';

function Controls({ player }: { player: VideoPlayer }) {
  const axis = useArrangementLayout()?.axis ?? null;
  const separated = axis !== null;

  const [shown, setShown] = useState(true);
  const visible = separated || shown;
  useEffect(() => {
    if (!visible || separated) return;
    const timer = setTimeout(() => setShown(false), 3000);
    return () => clearTimeout(timer);
  }, [visible, separated]);

  if (separated) return <Remote player={player} />;
  return (
    <Pressable style={{ flex: 1 }} onPress={() => setShown(!shown)}>
      {visible && <OverlayControls player={player} />}
    </Pressable>
  );
}
```

The example also restarts the timer on every interaction, and doesn't hide the controls while the video is paused or the seek bar is being dragged.

## Safe areas

The arrangement adds no safe-area padding. Let the video ignore the safe area so it stays centred on the display, and pad the controls instead. A separated pane doesn't reach the screen edge on its hinge side, so the axis also says which insets to skip:

```tsx
const insets = useSafeAreaInsets();
const leadingHinge = axis === 'horizontal';
const padding = {
  paddingTop: axis === 'vertical' ? 0 : insets.top,
  paddingBottom: insets.bottom,
  paddingLeft: leadingHinge && !I18nManager.isRTL ? 0 : insets.left,
  paddingRight: leadingHinge && I18nManager.isRTL ? 0 : insets.right,
};
```

## Full screen

The example's screen hides the stack header and the status bar, and turns off the back gesture, which on iOS 26 and later works anywhere on the screen and would take over drags on the seek bar:

```tsx
<Stack.Screen
  name="video-player"
  component={VideoPlayer}
  options={{
    headerShown: false,
    statusBarHidden: true,
    gestureEnabled: false,
    autoHideHomeIndicator: true,
  }}
/>
```

`statusBarHidden` needs `UIViewControllerBasedStatusBarAppearance` set to `true` in `Info.plist`. Apps can't turn off Android's back gesture, so the example excludes its seek bar from system gestures with [`setSystemGestureExclusionRects`](<https://developer.android.com/reference/android/view/View#setSystemGestureExclusionRects(java.util.List%3Candroid.graphics.Rect%3E)>).
